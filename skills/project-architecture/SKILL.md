# 项目技术架构文档（ARCHITECTURE.md）

参考标准架构模板，为当前项目生成/更新根目录 `ARCHITECTURE.md`，语言**简体中文**；完成后在本地开发规则中备注架构文档。

## 触发条件（严格限制：仅用户主动要求）

命中以下说法才使用本技能：

- 「生成架构文档 / 给项目写架构文档 / 更新架构文档」
- 「写 ARCHITECTURE.md / 初始化 ARCHITECTURE.md / 按模板生成架构文档」

以下情况**一律不触发**：

- 编写代码、修 bug、代码评审、需求分析等任何其他任务
- 用户只是问「项目架构是什么 / 用了什么技术」——直接基于现有文档与代码回答，不生成文档
- 发现项目没有 ARCHITECTURE.md 时，**不主动提议**生成；用户没要求就不提、不做

## 执行流程

| 步骤           | 动作                                                                                  | 要点                                                                          |
| -------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1 探索项目     | 读目录树、README、包清单（package.json / go.mod / pom.xml 等）、CI 配置、关键入口文件 | 弄清技术栈、目录分层、组件划分、数据流；证据优先，不臆造                      |
| 2 按模板生成   | 按 [references/template.md](references/template.md) 的 11 节结构填写                  | 全部简体中文；不适用的小节保留标题写「暂无」+ 一句原因，不删节                |
| 3 写入文件     | 保存为项目根目录 `ARCHITECTURE.md`                                                    | 已有旧版先读旧内容，保留其中仍有效的项目特定信息；更新「最后更新日期」        |
| 4 备注开发规则 | 在本地开发规则文件中追加架构文档备注                                                  | 按项目实际存在的规则文件为准（CLAUDE.md / AGENTS.md）；都没有则创建 CLAUDE.md |
| 5 汇报         | 文档路径、11 节完成情况、备注位置                                                     | 未能从代码确认的字段汇总为「待补充清单」，请用户提供                          |

开发规则中的备注格式（一句话即可，追加到已有文件末尾或对应章节）：

```markdown
## 项目架构

- 项目架构文档见根目录 [ARCHITECTURE.md](ARCHITECTURE.md)；了解项目结构、技术栈、组件与数据流前先读它。
```

## 填写规则

- 基于实际代码证据填写；确认不了的占位 `[...]` 保留原样并汇总到「待补充清单」，不要编造
- 第 9 节「未来规划」可综合 TODO、技术债、依赖版本给出建议，但每条必须标注「建议」
- 第 2 节系统图优先用文字块图（见模板示例）；交互复杂时可补 Mermaid 图增强可读性
- 术语表只收录项目专有术语与缩略语；通用技术名词不收
- 本文档定位是随代码库演进的「活文档」：后续用户要求更新架构文档时按同一流程增量更新，不整篇重写
- 用户要求对齐最新模板时，可参考 https://architecture.md/
