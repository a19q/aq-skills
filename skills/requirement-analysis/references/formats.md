# 标准需求格式识别表（11 种）

## EARS 句型（1–6，首选推荐）

| 类型 | 英文句式 | 中文句式 | 识别要点 |
| --- | --- | --- | --- |
| **1. 普适 (Ubiquitous)** | The \<system\> shall \<行为\> | 「系统应…」无触发条件 | 只有「系统/软件应做某事」，没有「当/如果/在…时」 |
| **2. 事件驱动 (Event-driven)** | **When** \<触发事件\>, the \<system\> shall \<行为\> | **当** [事件/操作]，系统应 [行为] | 明确「当…时，系统要…」 |
| **3. 状态驱动 (State-driven)** | **While** \<状态\>, the \<system\> shall \<行为\> | **在** [某状态] **下/时**，系统应 [行为] | 强调「在某种状态下」的持续行为 |
| **4. 可选特性 (Optional feature)** | **Where** \<具备某特性\>, the \<system\> shall \<行为\> | **若/在** [某特性存在] **时**，系统应 [行为] | 针对「有该功能/配置时」的行为 |
| **5. 非期望行为 (Unwanted behavior)** | **If** \<异常/错误条件\>, then the \<system\> shall \<行为\> | **若/如果** [错误/异常]，则系统应 [处理] | 错误、异常、边界条件的处理 |
| **6. 复杂 (Complex)** | When…, if…, the \<system\> shall… | 当…且如果…，系统应… | 同时含事件+条件或多个条件 |

## 其他五种（7–11）

| 类型                                  | 格式/句式                                | 中文示例                                        | 识别要点                           | 适用场景               |
| ----------------------------------- | ------------------------------------ | ------------------------------------------- | ------------------------------ | ------------------ |
| **7. 用户故事 (User Story)**            | As a [角色], I want [功能], so that [价值] | **作为** [角色]，**我想要** [功能]，**以便** [价值]        | 出现「作为…我想要…以便…」或强调角色与价值         | 敏捷、产品需求、优先级与价值沟通   |
| **8. 用例 (Use Case)**                | 参与者 + 主流程 + 备选流程                     | **参与者**：谁；**主流程**：步骤 1→2→3；**备选**：A1 失败→…   | 分步骤写主流程/正常路径，另有异常或分支流程         | 复杂交互流程（如登录、下单、审批）  |
| **9. Gherkin/BDD**                  | Given [前置], When [触发], Then [结果]     | **给定** [初始条件]，**当** [触发]，**那么** [预期结果]      | 出现 Given/When/Then 或「给定…当…那么…」 | 验收测试、ATDD、可执行场景    |
| **10. 需求模式 (Requirement Patterns)** | 领域标准句式（如安全、性能）                       | 系统应 [具体技术/指标]，如「对敏感接口实施 JWT，无 token 返回 403」 | 强调合规、安全、性能指标或技术约束              | 合规、安全、性能等非功能需求     |
| **11. 决策表 (Decision Tables)**       | 条件列 + 结果列，多行组合                       | 表：用户类型 \| 订单额 \| 活动 → 折扣率                   | 多条件组合决定同一结果，用表列出               | 复杂业务规则（定价、风控、权限组合） |

## 按意图推荐格式（描述不规范时用）

| 用户在说的内容 | 推荐格式 | 标准句式 |
| --- | --- | --- |
| 「在某种情况下系统要做某事」 | EARS 事件驱动 | **当** [具体触发]，**系统应** [具体行为] |
| 「谁要什么、为什么」、排需求优先级 | 用户故事 | 作为 [角色]，我想要 [功能]，以便 [价值] |
| 完整操作步骤、主流程与异常分支 | 用例 | 参与者 + 主流程（步骤 1→2→3）+ 备选流程（A1：失败→…） |
| 怎么验收/测试、可执行场景 | Gherkin | Given [前置]，When [触发]，Then [结果] |
| 安全/性能/合规等约束 | 需求模式 | 系统应 [具体技术或量化指标]（如 JWT、2 秒内、返回 403） |
| 多条件组合决定一个结果（如不同用户+金额+活动→折扣） | 决策表 | 条件列（…）→ 结果列，每行对应一种组合 |

## 句型速查（生成标准需求描述时用）

### EARS（1–6）

- **普适**：系统应 [行为]。
- **事件驱动**：**当** [谁在什么情况下做了什么]，系统应 [行为]。
- **状态驱动**：**在** [某状态] **下**，系统应 [行为]。
- **可选特性**：**在具备** [某特性] **时**，系统应 [行为]。
- **非期望行为**：**若** [错误/异常条件]，则系统应 [处理方式]。
- **复杂**：当…且如果…，系统应…。

### 其他五种（7–11）

- **用户故事**：作为 [角色]，我想要 [功能]，以便 [价值]。
- **用例**：参与者 + 主流程（步骤 1→2→3）+ 备选流程（A1：…→…）。
- **Gherkin**：给定 [前置]，当 [触发]，那么 [预期结果]。
- **需求模式**：系统应 [具体技术/量化指标]（如 JWT、2 秒内、403）。
- **决策表**：条件 1 | 条件 2 | … → 结果（多行组合）。
