# 判断与改写示例

以下示例演示「先识别、再回应」的实际做法：匹配到规范句型时先说明识别结果再继续；不规范时按意图推荐格式并给出 1 条改写示例。

- 用户：「加个登录，输了错密码要提示」
  → 识别：混合（事件驱动 + 非期望行为）。可回应：「您用了事件驱动（点击登录）和非期望行为（密码错误）两种 EARS 句型。建议拆成两条：① 当用户点击登录，系统应校验账号密码。② 若校验失败，系统应在输入框旁显示"用户名或密码错误"。」

- 用户：「页面别太卡」
  → 识别：不符合任一规范（模糊）。可回应：「当前描述不属于上述规范句型。建议改为可验证的 EARS 普适需求，例如："系统应在首屏加载后 2 秒内可交互"或"列表滚动时应保持 ≥60fps"。」

- 用户：「作为游客我想先看价格再决定注册」
  → 识别：用户故事。可回应：「您用的是用户故事格式。若要便于实现与测试，可再补一条 EARS：当未登录用户访问定价页时，系统应展示价格与套餐说明并允许查看，无需注册。」随后按需求继续开发建议。

- 用户：「用户登录：输入账号密码，点登录，系统校验，成功进首页，失败提示错误」
  → 识别：用例（主流程 + 备选）。可回应：「您用的是用例式描述（参与者 + 主流程 + 备选）。可规范为：用例名「用户登录」；主流程 1→2→3→4；备选 A1：校验失败→系统在输入框旁显示"用户名或密码错误"。」随后按需求继续。

- 用户：「新用户满 100 减 5，老用户满 200 且双十一打 85 折」
  → 识别：多条件规则，适合决策表。可回应：「您描述的是多条件业务规则，适合用决策表。可改为：列（用户类型、订单额、活动）→ 折扣/结果；每行对应一种组合。例如：新用户 | ≥100 | 无 → 5% 折扣；老用户 | ≥200 | 双十一 → 15% 折扣。」随后可协助画表或写 EARS。
