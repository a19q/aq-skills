# 项目报价

按前端开发视角（UI 开发、组件开发、逻辑开发、接口对接）把需求拆分为固定人天的报价明细，写入或追加到 Excel 报价工作簿。

## 何时使用

- 用户提供需求文档、用户故事、增补需求，要求出人天报价
- 用户要求在已有报价文件上继续追加、拆细、重排报价明细
- 用户要求基于「人天报价模板」创建新的报价文件

## 前置闸门：需求充分性检查（最高优先级）

**在写入任何报价明细之前，必须先通过这道闸门。**

只有当用户在当前对话中提供了可实际拆分为 UI开发 / 组件开发 / 逻辑开发 / 接口对接 的需求描述时，才允许生成报价明细。

以下信息**单独出现时视为需求不足**，不得据此推断任何明细：

| 不足的输入                                   | 说明                       |
| -------------------------------------------- | -------------------------- |
| 项目名称、版本号                             | 无功能信息                 |
| 文件名、sheet 名称、模板名称                 | 只是产物位置               |
| 一句笼统的功能标题                           | 无交互、无页面、无接口细节 |
| 「讨论报价规则 / 编写 skill / 确认分类口径」 | 不是报价请求               |

需求不足时的处理：

1. 如果用户已指定文件名、模板或 sheet：**只创建文件、sheet 和表头**，不写任何明细行
2. 明确提醒用户先发送本次要报价的具体需求内容
3. 停止编辑，等待补充

反例——下面这类输入只能创建空报价结构：

> 使用报价技能，模板参考人天报价模板，我要对某项目某功能进行报价，文件名为某某，有两个 sheet

## 核心规则

**始终以用户最新一条规则为准**，覆盖此文档中的默认约定。用户限制了报价明细写法时，只能使用用户允许的格式。

### 报价明细格式（D 列）

每条明细都是一句简体中文自然语言，不含特殊字符，且只能是以下三类之一：

| 明细结尾                     | 固定人天（E 列） |
| ---------------------------- | ---------------- |
| `...UI开发` 或 `...组件开发` | `0.5`            |
| `...逻辑开发`                | `1`              |
| `...接口对接`                | `0.5`            |

「从 UI 开发角度报价」应理解为**前端开发视角**，而非纯视觉页面——前端范围内的交互逻辑和接口对接同样纳入拆分。

### 类型列（C 列）术语映射

模板的类型列通常挂有数据验证下拉，允许值是模板自带术语（可能是繁体或英文），直接写简体术语会被 Excel 标记为非法值。

**写入前必须先读取目标 sheet 的 `data_validations`**，拿到允许值清单后按语义映射：

| 本技能术语            | 映射到模板允许值                                                                      |
| --------------------- | ------------------------------------------------------------------------------------- |
| `UI开发` / `组件开发` | 表示页面或界面那一项，如 `頁面`                                                       |
| `逻辑开发`            | 表示交互逻辑那一项，如 `邏輯`                                                         |
| `接口对接`            | 表示软件接口对接那一项，如 `軟件接口對接`（**不是** `接口`，**不是** `硬件接口對接`） |

模板没有完全对应的允许值时，**停下来跟用户确认映射**，不要硬塞简体值。

D 列明细文本仍按用户当次的语言习惯（简体或繁体）撰写，不受 C 列允许值影响。

## 输出文件位置

用户未指定路径时，**新建文件默认放在当前系统的下载文件夹**：

```bash
# macOS / Linux
QUOTE_DIR="$HOME/Downloads"
# Windows (Git Bash)
QUOTE_DIR="$USERPROFILE/Downloads"
```

规则：

- 新建报价文件：默认 `~/Downloads/<文件名>.xlsx`
- 从脚本重建模板：默认 `~/Downloads/人天报价模板PMX.xlsx`
- 用户给了绝对路径或明确目录：按用户指定，不要改写
- **目标报价文件已存在（当前目录或下载目录）：在原文件上追加，不要新建副本**
- 写入前用 `ls`/`Glob` 确认下载目录存在；不存在时先 `mkdir -p`
- 完成后向用户报出完整绝对路径

## 工作流程

1. **确认需求充分性** —— 未通过前置闸门则停止，只创建空结构
2. **定位文件** —— 在当前目录和下载目录查找报价模板与目标报价文件
   - 目标文件已存在 → 追加模式
   - 不存在但有模板 → 按模板创建到下载目录
   - 两者都无 → 用 `scripts/build_template.py` 重建模板
3. **读取结构** —— 确认列顺序、样式、合计位置、类型列数据验证允许值
   - 新建 sheet 时必须同步数据验证（见下）
4. **拆分需求** —— 按功能能力拆，而非机械按原文段落拆；一条明细对应一种类型和固定人天
5. **处理增补** —— 用户用全角括号标明的新增需求视为追加内容，其报价明细单元格标红
6. **写入** —— 优先 `openpyxl`；不可用时走 XML 兜底（见 `references/excel-xml-fallback.md`）
7. **核对** —— 序号连续、类型合法、人天正确、红字位置正确、合计同步

拆细替换：用户要求把一条汇总项拆成多条功能点时，**必须删除原汇总项**，避免重复报价。

### 复制 sheet 时同步数据验证

`openpyxl` 的 `wb.copy_worksheet` **不会**复制 `data_validations`。新建第二个及以上 sheet 时，逐条从源 sheet 读取 `DataValidation`，在新 sheet 上重新 `add_data_validation`，并保留原 `sqref` 范围，避免一个 sheet 有约束、另一个没有。

## 拆分判断规则

| 归类       | 典型内容                                                                 |
| ---------- | ------------------------------------------------------------------------ |
| `UI开发`   | 页面区域、工具栏、按钮、弹窗、选项区、结果展示区                         |
| `组件开发` | 可复用的图片标记区域、图层、容器、面板、图例                             |
| `逻辑开发` | 模式切换、表单联动、交互处理、绘制、缩放、清除、校验、条目合并、条件显示 |
| `接口对接` | 提交、回显、同步、保存、加载、调用后台数据接口                           |

一个需求含多个独立功能键或多个独立交互点时，在用户要求拆细时分别列出，不要合并：

- 鼠标功能切换交互逻辑开发
- 标记清除功能交互逻辑开发
- 图片放大功能交互逻辑开发

### 报价顺序

新增明细按自然开发顺序排列：入口界面与工具栏 UI → 各功能键交互逻辑 → 绘制与编辑逻辑 → 结果展示组件 → 后台记录或详情展示 UI → 接口对接。

用户明确要求调整顺序时，直接在原文件重排，不改内容和人天。

## 写入约束

- `A` 序号从 2 行开始递增连续
- `C` 类型只能用模板数据验证允许值之一
- `E` 人天按固定规则填 `0.5` 或 `1`
- 不要写入 `F` 列
- 不要修改或重写合计公式所在单元格
- 保留原有工作表结构和已有样式
- 优先复用已有共享字符串与已有红字样式
- 追加行后同步更新表格 `dimension` 范围
- 标红默认只作用于报价明细列（D 列），除非用户另有要求

## 辅助脚本

| 脚本                          | 用途                                                        |
| ----------------------------- | ----------------------------------------------------------- |
| `scripts/inspect_workbook.py` | 打印 sheet 列表、表头、数据验证允许值、最后数据行、样式索引 |
| `scripts/build_template.py`   | 在指定目录（默认下载文件夹）重建等价空模板                  |
| `scripts/append_rows.py`      | 从 JSON 追加报价行，自动映射类型、填人天、标红、更新序号    |

用法示例：

```bash
# 1. 检查 openpyxl 是否可用
python3 -c "import importlib.util; print(importlib.util.find_spec('openpyxl') is not None)"

# 2. 体检目标文件（先看清结构和允许值，再动手）
python3 scripts/inspect_workbook.py ~/Downloads/目标报价.xlsx

# 3. 没有模板时重建
python3 scripts/build_template.py            # 输出到 ~/Downloads
python3 scripts/build_template.py --out-dir . # 输出到当前目录

# 4. 追加报价行
python3 scripts/append_rows.py ~/Downloads/目标报价.xlsx --sheet Sheet1 --rows rows.json
```

`rows.json` 格式：

```json
[
  {
    "feature": "FR-02",
    "kind": "UI开发",
    "detail": "标记工具栏UI开发",
    "highlight": false
  },
  {
    "feature": "FR-02",
    "kind": "逻辑开发",
    "detail": "标记清除功能交互逻辑开发",
    "highlight": true
  },
  {
    "feature": "FR-02",
    "kind": "接口对接",
    "detail": "标记结果保存接口对接",
    "highlight": true
  }
]
```

`kind` 只填本技能四类术语，脚本自动映射为模板允许值并按规则填人天；`highlight: true` 表示增补需求，D 列标红。

## 过程与回复要求

开始查找分析前，给用户一句简短进度说明。准备改文件前，再说明将要追加或调整什么。

改完后核对：新增条目是否正确、类型是否合法、人天是否符合规则、红字是否只在需要位置、合计是否同步。

用户追问某点属于逻辑开发还是接口对接时，先给出明确分类判断，再按需更新文件。

回复保持简洁：说明更新了哪个报价文件（完整路径），概括本次新增或调整了哪些明细，报出本次新增人天与总人天。

因权限无法写入目标目录时，简短说明原因，并把文件保存到当前工作目录。
