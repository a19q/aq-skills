# PR body 模板

PR body 用**简体中文**，只描述最终功能，忽略开发过程、中间方案、重构改名等。

**只有一种格式，必须严格遵守**，不得增删小节、不得改用列表或标题层级：

```markdown
# 主要更新

<一句话概括变更>

Close #<ISSUE_ID>

PMX:#<编号>

PMX LINK:https://<链接>
```

## 字段说明

| 行                        | 说明                                           | 是否必须                     |
| ------------------------- | ---------------------------------------------- | ---------------------------- |
| `# 主要更新`              | 固定标题，逐字照写                             | **是**                       |
| 概括行                    | 一句话，中文不超过 100 字                      | **是**                       |
| `Close #<ISSUE_ID>`       | 关联 Issue 编号，MR 合并后自动关闭 Issue       | **是**                       |
| `PMX:#<编号>`             | 项目管理编号；**对话中命中需求号时取该需求号** | **是**                       |
| `PMX LINK:https://<链接>` | 需求链接                                       | **是**，<链接>没有提供则留空 |

## 严格约束

- 五行（标题、概括、Close、PMX、PMX LINK）顺序固定，之间各留一个空行
- **禁止**出现 `## 新增` / `## 调整` 等二级小节，**禁止**用 `-` 列表罗列要点；改动再多也只写那一句话概括
- 每行原文照写：`Close #`、`PMX:#`、`PMX LINK:https://` 前后都不加空格、不改大小写、不换标点
- 整段 body 只有这五行，不加结尾说明、不加分隔线、不加签名

Issue 创建后，其编号（IID）作为 `Close #<IID>` 写入 body。MR 创建时用 `-F <file>` 传入 body 文件。

注意 `Close #<ISSUE_ID>` 与 `PMX:#<编号>` 是两个不同的编号：前者是本次新建的 Issue IID，后者是对话中的需求号（如 `#8964` 对应 `PMX:#8964`），不要混用。
