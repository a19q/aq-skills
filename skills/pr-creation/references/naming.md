# 命名约束

规则优先级最高。任何来源（用户描述、Git 历史、模板、对话历史）产生的名称都要逐条对照，任一不通过即停止，不进入下一动作。

## 校验表（9 项）

| #   | 校验项            | 判定方法                                                                                                                                                                                                                             |
| --- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 分支格式          | 前缀只能是 `feat/` `fix/` `misc/` `release/` 四种之一，其他前缀（`hotfix/`、`chore/`、`docs/` 等）一律不合规；无前缀时补场景默认前缀。全名只用小写字母、数字、`-`、`/`，`/` 只出现一次                                               |
| 2   | kebab 段          | 去掉前缀与首段需求号后至少 2 个单词，且至少一个单词含字母（排除 `misc/20260907`、`release/1-2` 这类纯数字）                                                                                                                          |
| 3   | 长度              | 全名（含前缀与需求号）不超过 25 字符，超长先缩写/精简单词                                                                                                                                                                            |
| 4   | 禁止日期/版本式名 | `misc/20260907`、`misc/2026-0907`、`release/1.2.0`、`release/1-2` 一律不合规。可建议改为语义化 kebab（如 `release/phase-one-release`），但未经确认不得建分支、不得调用 API；用户坚持则停止执行                                       |
| 5   | 标题大小写        | 去掉 `#<需求号> ` 前缀后，**从左往右第一个英文字符改大写，其余英文字符一律小写**。不是「标题第一个字符大写」——数字/符号打头时继续往后找第一个英文字母。`#` 与数字之间、数字与正文之间各一个空格；除需求号 `#` 外不得出现其他特殊字符 |
| 6   | 逐词对齐          | 分支去掉前缀、剔除首段需求号后的 kebab 拆词，与标题去掉 `#<需求号> ` 后的单词**逐一对应、数量一致**                                                                                                                                  |
| 7   | 需求号三处一致    | 对话命中的需求号 = 分支首段数字 = 标题 `#<数字>`，三者完全相同                                                                                                                                                                       |
| 8   | Issue = PR        | Issue 标题与 PR 标题逐字符完全一致（含 `#`、空格、大小写）；PR 标题变更时同步变更                                                                                                                                                    |
| 9   | 表格与执行一致    | 最终建分支/建 Issue/建 MR 用的名称，与已输出的任务清单表格逐字符相同；中途改名必须重出表格                                                                                                                                           |

用户明确给出名称或标题时**不豁免**以上规则；违反则立即停止，不建分支、不调用 API、不擅自改写，说明违反项后等待指令。

## 第 5 项示例

只大写第一个英文字符，其余全小写——**不是** Title Case（每个单词首字母大写），也**不是**「标题第一个字符大写」：

| 分支                    | 正确标题           |
| ----------------------- | ------------------ |
| `feat/add-image-marker` | `Add image marker` |
| `misc/0907-fix`         | `0907 Fix`         |
| `fix/http-2-timeout`    | `Http 2 timeout`   |

## 数字段歧义（分支首段是纯数字时）

`0907 Fix` 与 `#8964 Image marker` 去掉 `#` 后形态相同，无法从字面区分「数字属正文」和「需求号漏写 `#`」。按需求号识别规则处理：

- 对话无需求号 → 数字属正文，分支与标题都不带 `#`（`misc/0907-fix` + `0907 Fix`）
- 对话有需求号 → 该数字必须是那个需求号，标题必须写成 `#<数字>`，不一致即停止
- 无法判断 → 停止并请用户确认

## 自检输出格式

自检结论随任务清单表格一起输出，逐项列出：

```text
命名自检：①分支格式 ✓ ②kebab 段 ✓ ③长度 ✓ ④无日期版本 ✓ ⑤大小写 ✓ ⑥逐词对齐 ✓ ⑦需求号三处一致 ✓ ⑧Issue=PR ✓ ⑨表格一致 ✓
```
