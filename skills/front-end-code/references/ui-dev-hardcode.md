# UI 开发阶段 hardcode 数据规则

> 适用范围：处于「先做 UI、接口后续接入」阶段的任务，包括写占位数据、还原设计稿、搭静态页面。接口已接入的正式数据流不适用本文件。

## 判断标准

问自己一句：**「这段逻辑将来是前端做还是接口做？」**——接口做的，UI 阶段一行都不要写。

## 核心思想

UI 阶段的数据是**占位**的。写得越像「真的数据流」，后续清理成本越高，还可能和真实接口的设计方向冲突。原则是：**直接、就地、无副作用。**

## 详细规则

- **数据就地定义，直接消费**
  mock 数据直接在使用它的 hook / 组件内定义为常量，渲染值直接派生。不为占位数据引入外部 store、全局状态、context 或订阅机制。

- **不模拟服务端职责**
  将来由接口完成的逻辑（条件过滤、搜索、排序、聚合），UI 阶段不在客户端复刻。筛选控件只保留受控 state 用于回显，**不驱动**本地数据变换。

- **不造配合逻辑的假数据**
  不要为了让某段过滤 / 分支逻辑「跑通」而构造一条注定会被处理掉的边界数据。需要什么状态就直接给什么状态，所见即所得。

- **字段跟着数据走，不要孤儿常量**
  属于某条记录的属性写在记录本身上，消费方从记录里取。不要把记录字段抽成独立全局常量再单独 import。仅当多条记录共享同一个无业务含义的字面量时，才提取为**文件内私有常量**去重，且不 `export`。

- **写操作无副作用**
  提交 / 删除 / 变更只做界面反馈（提示、关弹窗、跳转），不真改 mock 数据，也不写入 store。

- **跨页传值用路由，不用共享状态**
  详情页需要某条记录时，通过路由 state / 参数传递，不为此建全局 store。
